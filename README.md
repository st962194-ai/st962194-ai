# AIがどこで間違えるかを、先に書いてから渡しています

物流の現場で26年、受注から出荷・請求までの業務と現場作業の運営を担当してきました。
すでに動いている現場に後から入り、そこに合う形へ直す仕事です。

2026年1月から、同じやり方でAIに作業を任せる仕組みを作っています。

## やっていること

もともとは、要件整理とデータ定義を先に書いて、固めてから実装に入るやり方です。
何を作るか、何を作らないか、どのデータが正本か。ここを決めずに走り出すと、あとで全部やり直しになります。

そのうえで、どうしたいか、どうなってほしいかを、ひたすら言葉にして渡します。

AIを触り続けているうちに、どこで誤認識しそうか、どこで失敗しそうかが、先に見えるようになりました。
その心配事を、渡す前に書きます。書いた心配事は、あとで機械が止める形にします。
「たぶん大丈夫」で進めたところが、あとで事故になるからです。

コードを書くのはAIです。決めるのは、何を作るか、何を作らないか、どこで止まってほしいか、の3つです。

## いま試していること

一方で、先が見えない状態で作ることも始めています。
着地点が決まっていないまま、手を動かしながら形を探すやり方です。

これは自分にとって新しいやり方で、まだ慣れていません。
ただ、固めてから作るだけでは届かない範囲があることも分かってきました。
どちらの進め方も使えるようにしている途中です。

## 作り方の芯

**AIに任せる。ただし、入れていいものと出していいものの境界を、機械で止める。**

速く作ることより、止まるべきときに止まることを先に決めます。
止まらない仕組みは、誰も確かめられないからです。

## 手順

1. 何を作らないか、どこを触らないかを先に決める
2. AIに渡す。任せる範囲を書いて渡す
3. 報告ではなく、実物で確認する
4. 確認できていないことは、未確認として残す

## 記録の残し方

うまくいった話だけを載せません。
事前に何を心配し、何が起きて、どう直したかを、そのまま残します。
ai-commander-kit の記入例には、公開前に見つけた問題と、その対処が入っています。
